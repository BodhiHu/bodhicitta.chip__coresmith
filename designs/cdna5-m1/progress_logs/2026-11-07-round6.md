# 2026-11-07 — Round 6: softmax engine wired into WGP

## RTL integration
- `S_SOFTMAX` scalar opcode (`0x18`) added in `cdna5_m1_defs.vh`.
- `simd32` issues the descriptor (s[dst]=LDS base word, s[dst+1]=length) and
  waits in `S_SOFTMAX_W`.
- `wgp` instantiates `softmax_engine`, arbitrates it against WMMA/TDM, and
  forwards `softmax_done` to the issuing SIMD.
- `lds` gained a scalar 32-bit port (`reqs/wes/addrs/wdatas/rdatas/readys`)
  used by the softmax engine; `tb_wmma` ties it off.
- `scripts/synth.sh` includes `sfu.v` and `softmax_engine.v` for `wgp`/`top`.

## Verification
- `scripts/check_wgp_softmax.sh`:
  * equal 32 x 0: row sum **4064**, elements ~127
  * one-hot (first 4.0): first **1393**, other **87**, row sum **4090**
  * **PASS: wgp softmax path**
- `tb_top` (vecadd) still PASS, 32 cycles.
- `tb_wmma`, `tb_sfu`, `tb_softmax_engine`, `tb_wgp_softmax` compile/run.

## Synthesis
- `softmax_engine` standalone: 5,622 cells / 39,034.9 µm².
- Full `wgp` synthesis with the new engine was attempted; Yosys/ABC did not
  finish within the 600 s timeout (the combinational 32-bit divide is the
  likely critical cost).  No new WGP area figure is claimed.

## Known limits
- SFU is still standalone (not wired to an instruction).
- Top-level CSR/command path for `S_SOFTMAX` exists at the ISA/WGP level; a
  host kernel image can issue it, but the shipped `sw/` images do not yet
  include a softmax example.
- WMMA flat P&R remains open (1,024-bit LDS buses / 2,096 pins).
